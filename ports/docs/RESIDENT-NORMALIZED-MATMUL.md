# Resident normalization and projection

The frontend describes two numerical operations: `normalized = spatial::rmsnorm(x, w, epsilon)` and `projected = spatial::matmul(normalized, q)`, with independent explicit dataflow pragmas. The compiler recognizes their dependency and lowers a bounded typed subgraph to a resident CSL program. It does not choose an implementation by the application or variable name.

The normalization uses column-major row/feature tiles, feature-column weights, half square/add accumulation, an east-first bidirectional row reduction, and official SDK half square root. The contraction uses forward initial alignment and double-buffered two-hop communication, with explicit DSR FMA and CSL `@map`. Both execute within one host launch. The intermediate tensor is neither returned to Python nor recomputed by Python.

This first contract requires square projection weights, matching square 4×4 or 8×8 regions, half tensors, `fp=relaxed`, a single normalization consumer, and complete four-half communication packing groups. Shapes and the sum of planned buffers, observation storage and code/stack reserves must fit the PE budget. Input magnitude is limited to one. Arbitrary graph composition, QKV fan-out and persistent weights across independently changed calls remain unsupported.

## Logical tensors and physical buffers

The normalized tensor initially has ordinary row/feature tile ownership. Forward alignment permutes its private physical tiles for the contraction. The frontend value remains a logical tensor; the planner records that this sole consumer may destructively permute its storage. RMS square scratch becomes one communication buffer only after synchronous normalization has completed. Stable host input bindings remain separate from rotating working pointers. Projection weights are loaded freshly on each changed-input warm call.

The combined source communication implementation uses input/output queues 3 and 4 for reduction, 6 for broadcast, 7 for matrix X and 5 for matrix Y. Colors 1–11 configure these routes for the whole program. Async X/Y traffic uses explicit microthreads 0–3 and DSR 3/4; arithmetic uses DSR 1/2 in successive phases. Local tasks 19, 20, 25 and 26 preserve the source send/receive completion joins. A queue-empty observation is a witness at completion, not a substitute for those joins.

## Source and validation

The implementation derives from pinned WaferLLM Prefill commit `fd1c2daae37cd68706c03fc8009887ecee9900f8`. The one-time derivation script is outside the compiler; code generation instantiates reviewed CSL runtime files. [Provenance](NORMALIZED-MATMUL-PROVENANCE.json) records input and runtime hashes and changes. The already observed source RMS scale indexing problem is explicitly corrected, and weights follow the feature-column axis.

The source composition probe `prefill-rms-projection-20260906T225814493888Z` passed six SDK calls at 64×128 on 8×8 PEs. Normalization and projection both match their staged target-order half oracle exactly. Standard mathematical relative L2 errors range from zero to 0.006116 for the tiny-input epsilon case; ordinary projection cases are below 0.00175. These are source semantics results, not by themselves an HLS qualification.

The HLS build preserves frontend, checked and optimized IR, schedule, generated CSL, original C++ stdout, immutable implementation snapshots and raw SDK evidence. Sampled mode observes the entire normalized tile and every matrix accumulation prefix; counter mode omits those arrays. The debugger selects step 0 for normalization and steps 1–P for contraction prefixes, including consumed logical K blocks. Independent standard-math checks, exact target bits, warm-call counters, queue witnesses and bounded timestamps are checked separately.

The first HLS bundle `230645382091` passes all six SDK calls with exact normalized tensors, every contraction prefix and final output. It rejects all 20 evidence-corruption mutations. Its static ELF high water is 12,464 bytes. Matched input/source output checks also pass; sampled timings (17,716 HLS versus 19,517 source cycles on ordinary inputs) include different observation-copy implementations, so they are not an isolated computational speedup. Counter-mode HLS `231301101651` and source `231558529966` both pass six changed calls. Exact matching outputs give maximum local intervals 17,423/17,308 on ordinary inputs, or 0.6644% HLS overhead. Both omit tensor observations; the remaining phase counters and queue witnesses differ explicitly. The sampled HLS adds 293 cycles (1.6817%) over its counter mode. The larger 128×256 execution remains in progress. This composition is not yet catalog-registered. Current timings are WSE3 simulator local intervals; no wafer hardware performance claim is made.
